# th128(妖精大戦争 ～ 東方三月精)対応の技術的背景(Issue #78、touhou-recorder reports/70〜73)

メインシリーズと同じ上海アリス幻樂団(ZUN)制作の外伝作品(黄昏フロンティアの格闘ゲーム
シリーズとは別)。**TH10エンジンをベースにしており(thprac側の`thprac_th128.cpp`が
th10用のトラッカーコールバックをそのまま再利用)、入力方式・スコア監視の作りは
th10/th12の延長線上にある**一方、**thprac無しでは録画できない既知バグを持つ点は
th20と同じ**という、両者のハイブリッドに近い構成。sattori本体の`record_th128.py`での
ローカル実機検証結果は
[`docs/reports/2026-09-09-th128-local-recording-verification.md`](../../../docs/reports/2026-09-09-th128-local-recording-verification.md)。

touhou-recorder での事前検証(reports/70〜73)を踏まえた設計:

- **入力注入はth10/th12と同じPressKey(DIKスキャンコード経由)**: DirectInputの
  `GetDeviceState`が実際に55〜60Hzでポーリングされることを実機確認済み(`FpsMonitor`
  ログ、reports/70)。`InstallKeyboardStateHook`は不要。
- **メニュー操作シーケンスはth11/th12と異なりDown x1のみ**(ユーザー指定どおり):
  タイトル画面ロード待ち(8000ms、th10の6000msよりやや長め) → Down x1 → Enter
  (Replay選択) → Right(ユーザーリプレイタブへ切替) → Enter(1番目のユーザーリプレイ
  選択) → Enter(再生確定)。リプレイ一覧はth11/th12/th20と同じ`_ud0000`タブ切替方式
  (番号スロット方式のth06〜th10とは異なる)。
- **`thprac`(`thprac.v2.3.0.3.exe`)が無いと録画できない**: リプレイ選択画面で
  1番目のユーザーリプレイを確定するEnterの直後、`GetDeviceState`の呼び出しが
  完全に停止しゲーム本体が無限ループでフリーズする既知バグがある(Windows実機でも
  再現するゲーム本体側の既知バグとユーザーから確認済み)。thpracを経由して起動する
  だけで解消することを実機確認済み(reports/70)。`record_th128.py`は`thprac_exe`を
  常に指定しており、これを外さないこと(th20と同じ運用、`worker/docs/titles/th20.md`
  参照)。
  > `--thprac`と低速録画(`FPS_LIMIT_TARGET_HZ`<60)を併用する場合、thpracアタッチの
  > 待ち時間も`MENU_TIME_SCALE`でスケールしないとタイムアウトする(reports/72で
  > 発覚・修正済みの不具合。`recording.process.attach_thprac()`の呼び出し側が対応済み)。
- **cfg/リプレイの配置場所はth20と同じ`%APPDATA%/ShanghaiAlice/th128/`配下**
  (`uses_appdata_profile=True`)。th128.cfgの先頭バイトは`0x01`(ウィンドウモード、
  th12.cfgと同じ値)であることを確認済み。
- **終了検知はテンプレート照合を使わず、画面静止検知のみで運用する**: 再生終了画面は
  「STAGE CLEAR」表示+直前ゲームプレイ画面の凍結+Pause Menuオーバーレイという、
  リプレイ内容に依存して背景が変化する構造(th11の終了画面と同じ構造、
  `worker/docs/titles/th11.md`参照)のため、内容非依存の固定テンプレートが作れない。
  Pause Menuの項目文字自体は明滅しないため、th11で必要だった
  `still_detect_exclude_rect`も不要(reports/71)。
- **スコア・やる気ゲージの監視RVA**: thprac(`thprac_th128.cpp`)の`th128_patch_main`
  フック内で練習モードの初期値をゲーム内変数へ直接書き込んでいる箇所の絶対VA
  (image base `0x400000`)から収集し、基点`0x4b4c00`(RVA=`0xb4c00`)からのオフセット
  に整理したもの。scoreは`+0xc4`(内部値は画面表示値の1/10、他タイトルと同じ×10系列)、
  motivation(「やる気」ゲージ、残機に相当)は`+0x164`(表示値は生値/100)。フル尺録画
  (通常・Extra両方)で記録スコアとの完全一致を実機確認済み(reports/71)。グレイズは
  th128エンジンに実装が見当たらない(thprac側もTHPracParamにgrazeフィールドが無い)
  ため計測しない。perfect_freeze(ボム相当)・ice_power・ice_area(こおらせた面積)の
  RVAもHUD照合で特定済みだが、score_monitorには未接続(任意、reports/70〜71)。
- **推奨インスタンスタイプは`.2xlarge`帯(8vCPU)**: `.xlarge`帯(4vCPU)ではExtra
  ステージの理論尺超過率が+4.16%(重複フレーム率5.5%)まで悪化する一方、
  `c7i.2xlarge`(8vCPU)では+0.71%(1.4%)まで改善することを実機確認済み(reports/73)。
  th11・th12と同じ`c7i.2xlarge`/`c7a.2xlarge`/`m7i.2xlarge`の「`.2xlarge`帯実機検証済み
  グループ」([`decisions/0042`](../../../docs/decisions/0042-2xlarge-instance-type-group-precedent.md))
  の対象として扱い、`c7i.2xlarge`1タイプの実機検証のみで残り2タイプも候補に追加した。
- **低速録画フック(`fps_limiter_hook`/`dsound_hook`)は実装・実機検証済み(30fpsで重複
  フレーム率50.2%、理論値どおり、reports/72)だが、Sattori側の
  `SLOW_MOTION_SUPPORTED_GAME_IDS`には未登録**(th09と同じ位置づけ。Issue #78の
  スコープ外、将来Issue #101で他タイトルへ展開する際にそのまま使える)。

## 残っているリスク

- fps表示補正(`fps_display_hook`)は未接続のため、低速録画時の画面上fps表示は
  未補正のまま(録画パイプライン自体の動作には影響しない、reports/72)。
- perfect_freeze/ice_power/ice_area/stage(route)はscore_monitorに未接続(任意、
  デシンク事後検知に必須なscore/motivationは接続・検証済み)。
