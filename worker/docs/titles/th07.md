# th07（東方妖々夢）対応の技術的背景

最初に録画対応したタイトルで、他タイトルはここでの実装（`recording/` パッケージの共通
パイプライン）を基準に差分を足す形になっている。**Wine 上での日本語フォント・ロケールの
扱いは th07 の検証で確立したもの**なので、フォント関連を触る前にここを読むこと。

事前検証は touhou-recorder の reports/11・13・14・16・17・21。

## 日本語フォント（MS ゴシック）の配置・レジストリ登録が必要（th07・th08共通）

th07・th08の`th{N}.exe`はGDIのフォント名指定にShift_JISで`ＭＳ ゴシック`をハードコードして
おり、これに対応するフォントファイル・レジストリがWINEPREFIXに無いと、
タイトル画面やスペルカード名等の動的描画テキストが文字化けする
(touhou-recorder reports/13, reports/29)。th07には元から適用されていたが
th08には未適用だったため、本番で文字化けが発生していた(2026-07-23に修正・
再アップロード済み)。

配置・レジストリ登録は `worker/setup_wineprefix.sh` がやる（実行手順は
`upload-title-assets` skill）。`msgothic.ttc` は Windows のライセンスフォントであり、
著作権上リポジトリにも S3 にも単体では置いていない。

th11 以降はこれに加えて MS明朝（`msmincho.ttc`）も要る（[`th11.md`](th11.md)）。

## 日本語ロケールはWINEPREFIXではなく実行時に設定する

日本語ロケール(`LANG=ja_JP.UTF-8`/`LC_ALL=ja_JP.UTF-8`)はWINEPREFIX作成時ではなく
`recording.config.GameConfig.build_env()`が起動時に毎回設定する(`setup_wineprefix.sh`では扱わない)。
reports/13で「WINEPREFIXが英語ロケールで初期化されているとANSI文字列の変換が
壊れる」問題が見つかったが、対策はプレフィックス再作成ではなく実行時の環境変数で
足りると判明したため。

## VsyncPatch（`vpatch_th07.dll`）で桜点の表示崩れを直す

th07 には桜点（画面左下の数値）が大きくなりすぎると表示が崩れる既知の不具合があり、
ファン製パッチ「VsyncPatch」（`vpatch_th07.dll`）の `BugFixCherry` オプションがこれを
修正する（`games/th07/vpatch.ini` で有効化済み）。th06 と同じ `GameConfig.extra_dlls` の
仕組みで、MOD 本体（`th07_hook.dll`）より前に同一プロセスへ注入する
（`recording.instance.build_injector_cmd()`）。DLL 本体はタイトル資産アーカイブの
`games/th07` に同梱しておけば `prepare_instance()` の rsync でコピーされる。

## 解像度（640x480）

640x480 で録画されるため、そのままだと YouTube 側で 60fps と認識されない。配信版は
960x720 へ拡大する（touhou-recorder reports/21）。生データ（元解像度版）は無加工で
2本目として配信できるので、再エンコードは配信版の1回だけで済む（`worker/README.md` §4）。

## 終了検知

リプレイ選択画面テンプレート（`assets/replay_end_templates/th07.png`）との照合で判定する
（[`docs/decisions/0011`](../../../docs/decisions/0011-replay-end-template-matching.md)）。

## クロップ座標

2026-07-28 のゲームデータ差し替え時の再検証で、th07 でもウィンドウ装飾（タイトルバー）が
ゲーム画面上端に重なって下端が録画されない事象が偶発的に再現した。座標の確定手順は
全ゲーム共通で [`docs/decisions/0012`](../../../docs/decisions/0012-crop-geometry-after-window-stabilizes.md)
にまとめてある。
