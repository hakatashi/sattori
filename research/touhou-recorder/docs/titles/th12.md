# 東方星蓮船 (th12)

## 基本情報

- 画面解像度: 640x480 (4:3)
- 描画API: Direct3D9
- 推奨クラウドアスペクト: **8 vCPU以上 (`.2xlarge`帯、`c7i.2xlarge`推奨)**

## 固有仕様・運用ルール

- **クラウド必要スペック**: 4 vCPU（`.xlarge`帯）では重複フレーム率自体は低く見えても、リプレイの `frameCount` との理論尺比較で通常ステージに+2.11%の処理落ちが隠れていました。8 vCPU（`.2xlarge`帯）では+0.16%まで改善し、Lunatic難易度でも+0.21%と良好に録画できます。
- **リプレイ終了検知**: 画面静止検知のみで運用し、`still_detect_exclude_rect` で明滅・アニメーション領域を除外します。

- **文字のジャギー(reports/101・102)**: 会話文は `D3DXLoadSurfaceFromMemory`(730x36→354x17、`D3DX_FILTER_TRIANGLE`)の縮小転送で、Wine では最近傍になる。`D3DX_AREA_FILTER=1` で MOD 側のテント縮小に置き換わる(既定は無効)。`c7i.2xlarge` 等倍の AWS 比較で、フィルタの有無による品質差は無かった。ただし**フィルタなしでも落ち3.1〜3.3%・理論尺+1.8〜2.1%で、reports/98 の基準外**(`c7i.2xlarge` 推奨は基準の策定前の評価。`c7i.4xlarge` か 1/2倍速の検討が要る、未検証)。

- **フレーム同期キャプチャ (`--frame-sync`、reports/109)**: `mods/common/frame_sync_hook.cpp` に `MyGetRasterStatus` (`IDirect3DDevice9::GetRasterStatus` `vtable[19]`) フックを追加したことで AWS `Xvfb` 上の 60fps 頭打ちが解除され、AWS CPU スポットで **`c7i.4xlarge` 2.31〜2.33倍速**・**`c7i.2xlarge` 1.76倍速**（従来 `c7i.2xlarge` 等倍比で費用・課金時間を約32%削減しつつ品質基準外を解消）・**`m7i.xlarge` (4 vCPU) 1.10〜1.13倍速**、GPU 4 vCPU の **`g6f.xlarge` 1.00倍速** を確認。ローカル16並列CPU飽和負荷(`0.19x`)や `c7i.2xlarge` 8並列負荷(`0.60x`)を含め全本で試行1回目成功・スコア一致・ドリフト`[0,0,0]`・`A/V差=0.0ms`・プレイ区間落ち`0.0%(Hard) / 0.1〜0.2%(Extra)`を達成しており、GPU を使わず CPU の `.2xlarge` / `.xlarge` で基準を満たせる。
