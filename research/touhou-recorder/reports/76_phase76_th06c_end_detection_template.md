# フェーズ76: th06cのリプレイ終了検知をテンプレート照合に対応

フェーズ75の残課題のうち、ユーザー指示により「リプレイ終了検知のテンプレート照合対応」のみを
実施した(低速録画・ステージ番号等のRVA特定・AWS実機検証は今回のスコープ外)。

## 背景

th06cはリプレイ再生が終わると、内容非依存のリプレイ選択画面
「瀟洒なるリプレイを見よう!」へ戻る(フェーズ75で実機確認)。しかしフェーズ75時点では
`end_template` を未設定にしていたため、画面静止検知(`STILL_CONSECUTIVE_REQUIRED=8`、
= 16秒の静止待ち)のみで終了を判定しており、録画の末尾に無駄な尺が付いていた。

## 1. テンプレート画像と照合領域の決定

### 1.1 背景アニメーションの有無

th10(`reports/56`)やth09(`reports/68`)ではリプレイ選択画面の背景が常時アニメーション
しており、上部の帯全体を比較すると同一画面同士でもMADが上振れする問題があった。
th06cについて実測したところ、**背景も含めて完全に静止していた**。

```
Extra録画の630秒時点と636秒時点の全画面MAD = 0.001
```

### 1.2 内容依存領域の除外

一方、リプレイ一覧の行(`No.04 koyi 09/10/26 ReimuA Extra` 等)はリプレイごとに変わる。
640x480座標系での実測:

| 領域 | y範囲 | 別リプレイ間のMAD |
|---|---|---|
| タイトル文言「瀟洒なるリプレイを見よう!」 | 84〜108 | — |
| 列見出し「No. Name Date Player Rank」 | 126〜150 | — |
| **見出し帯(タイトル+列見出し)** | **78〜152** | **0.001** |
| 一覧行(1行目) | 155〜185 | **3.01** |
| 既定のEND_TEMPLATE_ROWS(上部1/3) | 0〜160 | 0.002 |

既定の上部1/3でも実用上は問題ない値だが、一覧行の上端(y=155)にかかっており、
リプレイ本数が増えて行が伸びた場合に不安定になりうる。そこで
`end_template_rect = (20, 78, 560, 152)` を明示指定し、**見出し帯だけ**を照合対象にした。

### 1.3 識別性能の実測

`assets/replay_end_templates/th06c.png` は、Extraフル尺録画の630秒時点のフレーム
(640x480、リプレイ選択画面)から切り出した。

| 比較対象 | MAD |
|---|---|
| 別時点のリプレイ選択画面(同一リプレイ) | 0.00 |
| **別リプレイ**のリプレイ選択画面(Hard版) | 0.00 |
| ゲームプレイ中のフレーム(15点サンプル) | 35.5 〜 113.9 |

閾値は既定の `END_TEMPLATE_MAD_THRESHOLD = 15.0` をそのまま使う
(`end_template_mad_threshold` の個別指定は不要)。

### 1.4 録画全体を1秒刻みで走査した誤検知チェック

```python
# ffmpeg -vf fps=1,scale=160:120,format=gray でrawvideoを取り出し、
# end_template_rect相当のマスク領域でMADを計算
```

| 録画 | 走査フレーム数 | 閾値15.0未満のフレーム | うち**再生中**(録画開始15秒〜終了検知)のもの |
|---|---|---|---|
| Hard (`th6_01`) | 1568 | 23件 | **0件** |
| Extra (`th6_04`) | 642 | 22件 | **0件** |

閾値を下回ったのは「再生開始前のリプレイ選択画面(録画開始5〜6秒付近)」と
「リプレイ終了後」だけで、再生中の誤検知はゼロだった。再生開始前の一致は
`POST_START_GRACE_SEC`(15秒)の猶予期間中なので終了判定には使われない。

## 3. 【バグ修正】検知方式のラベルが常に「画面静止検知」になっていた

テンプレート照合の動作確認中に、**終了検知の方式によらずサマリー行が
`検知方式: 画面静止検知` と表示される**不具合を発見した。

```
[19:28:01] リプレイ選択画面と連続して一致したため、リプレイ終了と判定しました
[19:28:01] 録画終了。総録画時間: 77.1秒 検知方式: 画面静止検知   ← 誤り
```

原因は、テンプレート照合側と画面静止検知側が同じ `detected` フラグだけを立てており、
サマリー生成箇所(`attempt_recording` 末尾)が `elif detected:` で
`stop_reason = "画面静止検知"` を固定で入れていたこと。

`detected_by`(`"template"` / `"still"`)を追加して分岐するよう修正した。
**この不具合はth06cに限らず、テンプレート照合を使う全タイトル
(th06 / th07 / th08 / th09 / th10)のログ・レポートに影響していた**
(判定結果そのもの・`classification` は正しかったので、録画動作への影響はなく表示のみ)。

修正後:

```
[19:30:53] リプレイ選択画面と連続して一致したため、リプレイ終了と判定しました
[19:30:53] 録画終了。総録画時間: 77.0秒 検知方式: リプレイ選択画面テンプレート照合
```

## 4. 効果の実測

録画動画そのものを `fps=2` で走査し、「リプレイ選択画面が出現した時刻」と
「録画の総尺」の差(= 終了検知にかかった余剰尺)を測った。

| 録画 | 検知方式 | 総尺 | 終了画面出現 | **末尾の余剰** |
|---|---|---|---|---|
| `th06c_tmpl_test2.mp4` (`th6_05`) | テンプレート照合 | 77.0秒 | 72.5秒 | **4.5秒** |
| `th06c_extra_full.mp4` (`th6_04`) | 画面静止検知 | 641.5秒 | 621.0秒 | 20.5秒 |
| `th06c_hard_full.mp4` (`th6_01`) | 画面静止検知 | 1567.5秒 | 1547.0秒 | 20.5秒 |

**録画1本あたり約16秒の短縮**。これは
`END_TEMPLATE_CONSECUTIVE_REQUIRED = 2`(2 × POLL_INTERVAL_SEC ≒ 4.4秒)と
`STILL_CONSECUTIVE_REQUIRED = 8`(≒ 20秒)の差に対応しており、設計どおりの結果。

## 5. 再現手順

```bash
# テンプレート画像の切り出し(既存のフル尺録画から)
ffmpeg -ss 630 -i runs/th06c_verification/th06c_extra_full.mp4 -frames:v 1 \
    -y assets/replay_end_templates/th06c.png

# 動作確認(短いリプレイで十分)
python3 scripts/25_record_replay_e2e_multigame.py --game th06c --replay th6_05.rpy \
    --output runs/th06c_verification/th06c_tmpl_test2.mp4
# -> 検知方式: リプレイ選択画面テンプレート照合
```
