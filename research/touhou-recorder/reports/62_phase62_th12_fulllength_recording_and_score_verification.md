## 事前準備: PulseAudio専用シンクの残骸クリーンアップ

作業開始前(フェーズ61末)にsattori-home-workerサービスを停止していたが、そのサービスが最後に実行したジョブ(th08、フェーズ61冒頭で確認)が作成した専用null-sink(`sattori_job_local_3077848`)がアンロードされないまま残っていた。AGENTS.mdの「専用シンクを1つでも追加すると既存の`auto_null`は自動的にunloadされる」という記載通り、`auto_null`が存在しない状態になっており、th12初回のフル尺録画試行で音声ffmpegが`Error opening input file auto_null.monitor.`で失敗した(映像側は正常に録画継続、重複フレーム率計測には影響なし)。

`pactl unload-module 19`(残骸シンクのモジュールID)で削除したところ、`auto_null`が自動的に復活し、以降の録画で音声取り込みが正常に機能した。**単一インスタンス運用でも、直前に並列録画運用や別ジョブが専用シンクを作成した形跡がないか、録画前に`pactl list short sinks`で確認する価値がある**ことが分かった教訓として記録する。

## 通常ステージ: th12_02.rpy(ReimuB / Hard / Stage All Clear)フル尺録画

```bash
TIMEOUT_SEC=2700 python3 scripts/25_record_replay_e2e_multigame.py --game th12 --replay th12_02.rpy \
  --output runs/th12_verification/th12_normal_full_<epoch>.mp4
```

- 総録画時間: 1768.6秒(≒29.5分)。画面静止検知で正しくリプレイ終了を検知。
- **録画開始15秒以降の重複フレーム率: 0.0%**(このローカル開発機での実測)。
- 映像640x480@60fps・音声AAC(48kHz)ともに正常。`ffmpeg -af silencedetect`で無音区間を検査したところ、リプレイ終了直前の演出停止区間(1748.2秒〜1766.8秒、約18.6秒)以外に無音区間は無く、音声トラックが録画全体にわたって継続的に取り込めていることを確認した。
- A/V同期補正ログ: `video_start=... audio_start=... delta=+0.590s`を検出し、`-itsoffset`でmux(AGENTS.md記載の標準方式が正常機能)。
