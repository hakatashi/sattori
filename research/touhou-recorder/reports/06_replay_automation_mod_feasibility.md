# フェーズ6: リプレイ自動再生MOD案の実現可能性調査

日付: 2026-07-15

## 背景

フェーズ3(`03_phase3_input_reliability.md`)で判明した通り、`xdotool`による外部からのキー入力シミュレーションはメニュー操作の信頼性が低く、リプレイ自動再生の実現を阻む最大の課題として残っている(`AGENTS.md`の★最重要の未解決課題)。

この課題への別解として、「ゲームデータを改変し、起動→ロード完了後に自動でリプレイ再生メニューを選択して1番目のリプレイを再生するMODを作る」という案が浮上した。過去に東方花映塚(TH09)で、DLLインジェクションによりメニュー自動操作(対戦モード自動開始MOD)に成功した実績があり(`docs/touhou_menu_automation.md`)、その知見を本PoCに応用できるかを調査した。あわせて、ファンコミュニティ製のMOD作成ツール`thcrap`(https://github.com/thpatch/thcrap)が活用できるかも検討した。

## 結論

**実現可能性は高い。** TH09で確立した「DirectInput `GetDeviceState` vtableフック」方式は、xdotoolが失敗している根本原因(Wine側DirectInputのポーリングタイミングに外部X11キーイベントが同期しない)を技術的にバイパスする手法であり、原理的にリプレイ選択メニューにもそのまま適用できる。**推奨アプローチは、thcrapを介さずTH09の知見を直接移植した自作DLLインジェクションである。** thcrapは本用途の完成品ではなく、導入する場合もカスタムコード実装は結局自分で書く必要があるため、今回は採用しない方が効率的と判断した。

---

## 1. なぜvtableフック方式がxdotool問題を解決しうるか

`docs/touhou_menu_automation.md`によれば、東方ゲームのメニューは**DirectInputの`GetDeviceState`が返す生バッファ(BYTE[256])を直接読む**。`xdotool`が送るX11キーイベントは、Wineの X11 ドライバ →(何らかの変換)→DirectInputのポーリング、という経路を通る必要があり、この経路のタイミングが非決定的であることがフェーズ3で観測された不具合(移動量のばらつき、決定キーが方向キーと区別されない現象)の実体と考えられる。

一方、vtableフックは**この経路そのものを乗っ取り**、ゲームが`GetDeviceState`を呼んだ瞬間に確実に狙ったバッファ値を返す。TH09では以下の手法のみが機能した:

- IATフックで`DirectInput8Create`をフック
- `IDirectInput8A::CreateDevice`(vtable index 3)をフックしてデバイス取得を捕捉
- `IDirectInputDevice8A::GetDeviceState`(vtable index 9)をフックしてバッファ改ざん

この方式は**メモリアドレスやゲームバージョンに依存しない**(vtableのインデックスはDirectInput 8のABIとして固定)ため、逆アセンブル・アドレス特定なしに他タイトルへ移植できる可能性が高い。

## 2. リプレイ自動再生特有の追加検討事項

TH09の「対戦自動開始」と比べ、「リプレイ再生」には以下の追加調査・実装が必要:

1. **メニュー階層のマッピング**: メインメニュー→Replay→リプレイ一覧→1件目選択→決定、という遷移をタイトルごとに実機確認する必要がある(既存ドキュメントの「移植チェックリスト」item 4 と同じ作業)。フェーズ3で「Replayへのカーソル到達」はxdotoolでも複数回成功しているため、階層自体の把握は難しくない。
2. **リプレイ一覧の非同期読み込み**: リプレイファイル一覧の描画がロード完了後に遅延する可能性がある。ドキュメントの「起動完了検出」(HWND安定+DI初期化+バッファ待機)と同様の考え方で、「リプレイ一覧が描画完了するまで待つ」段階を追加する必要がある。
3. **タイトルごとのリプレイ形式差異**(`games/`調査より判明):
   - th06: `REPLAY/`(大文字)、`.RPY`、`T6RP`マジック(旧世代形式)
   - th07〜th10相当: `replay/`、`.rpy`
   - th11以降: `t11r`マジック(新世代形式)
   形式の違い自体はメニュー操作(UI)に影響しないはずだが、確認が必要。
4. **dinput8.dll依存の再確認**: 移植チェックリスト通り、対象タイトルの`strings thXX.exe | grep -i dinput`でDirectInputのバージョンを確認する必要がある。特にth14以降で入力APIが変わっていないか未検証。
5. **32bit DLLビルド環境**: 東方シリーズは全タイトル32bitのため、32bit DLLのビルド環境(MinGWクロスコンパイルまたはWindows上でのVisual Studio)が必要。
6. **Wine環境でのDLLインジェクション手法の再検証**: TH09での成功事例が実機Windows上だった場合、Wine上での`CreateRemoteThread`+`LoadLibrary`相当や、前回使用した[ka_ai_duka](https://github.com/kory33/ka_ai_duka)インジェクタがWine環境でも動作するかは未検証。Wineは概ねこれらのWin32 APIをサポートしているため動作する可能性は高いが、実地検証が必要。
7. **前提となる起動阻害要因の解消が先決**: th06(wined3dハング、未解決)とth13/14/15/20(Steam DRMによるexit code 53)は、MODの実装以前に**そもそもヘッドレス環境で起動すらできていない**。これらのタイトルはMOD開発着手の前提条件として起動問題の解決が必要。

## 3. thcrapの調査結果

### アーキテクチャ

thcrapは自作MODと同系統の**DLLインジェクション方式**(+一部バイナリパッチ)。`thcrap_loader.exe`が新規プロセスを生成しインジェクションし、`thcrap.dll`がパッチ・フック適用を統括する。子プロセスにも伝播するため他のインジェクションツールとの併用も可能。ゲーム別プラグイン(`thcrap_tsa`等)でTH本編エンジンのフック定義を提供している。

### breakpoints / binhacks 機能

- **binhack**: 指定アドレスのバイナリ直接書き換え
- **codecave**: 注入コードブロックの実行
- **breakpoint**: 指定アドレス到達時にカスタムDLL関数を呼ぶフック

いずれも**ゲームバージョンごとにアドレスをJSONで定義する**方式であり、「ロード完了アドレスにbreakpointを置き、キー入力状態を注入する」という設計は理論上可能だが、**結局カスタムハンドラのC++実装とアドレス特定が必要**で、自作DLLインジェクションと実装コストは大差ない。むしろ我々のvtableフック方式はアドレス非依存な分、thcrapのbreakpoint方式より移植性で有利な面がある。

### 対応タイトルと先行事例

- TH06〜TH20まで公式に対応(TH09/花映塚も対応範囲内)
- **`devinacker/TouhouKeymap`**というthcrapプラグインが、キーリマップ目的で「DirectInput有効/無効どちらでも動作する」入力層フックを実装しており、**我々のvtableフック方式と同系統のアプローチがコミュニティで実証済み**という傍証になる(PoFV/TH09にも対応)。
- 「起動時オートプレイ/デモ自動再生」的な完成済みパッチは確認できなかった(不明)。

### ライセンス・配布

パブリックドメイン。完全オープンソースで、独自のbreakpointハンドラ・プラグインDLLを追加できる。ビルドはVisual Studio 2019+、Jansson/libpng/zlib等に依存。

### 採用判断

| 観点 | 自作DLL(TH09知見の移植) | thcrap経由 |
|---|---|---|
| 実装済み実績 | ○ TH09で動作確認済み | △ 参考事例(TouhouKeymap)はあるが自前実装は必要 |
| アドレス特定の要否 | 不要(vtableインデックスは固定) | 必要(バージョンごとのbreakpointアドレス) |
| 学習コスト | 低(既存コードの流用) | 中〜高(thcrapのJSON形式・ビルド環境) |
| 複数タイトル/バージョン対応の将来性 | タイトルごとに手動移植 | フレームワークとしての将来的なスケール性はやや高い |
| 今回のスコープとの適合 | ◎ 単機能(自動再生)に対して軽量 | △ オーバーヘッドが大きい |

**結論として、今回は自作DLLインジェクション方式を採用する方が効率的**。thcrapは将来的に「多数のタイトル・バージョンを正式にサポートするMODとして配布したい」といった要件が生じた場合の選択肢として記録に留める。

## 4. 次のアクション(提案)

1. まず th07 / th08(既に描画・fps実証済み)を対象に、TH09の3段フック(IAT→CreateDevice→GetDeviceState)をそのまま移植し、Wine環境でのDLLインジェクションが機能するかを検証する
2. `strings th07.exe th08.exe | grep -i dinput`でDirectInputバージョンを確認
3. リプレイメニューの階層・カーソル位置を実機確認(スクリーンショットベース)
4. th06のwined3dハング、th13以降のSteam DRM問題は本MOD開発の前提条件として別途解決が必要(既知の未解決課題)
