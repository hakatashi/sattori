# フェーズ14: 終了検知の誤検知修正(MAD閾値の見直し)

日付: 2026-07-15

## 背景

`scripts/11_record_th07_replay_e2e.py`を用いて通常ステージのリプレイファイル`th7_09.rpy`(総再生時間約30分)を録画したところ、ゲームプレイ中にもかかわらず「画面に変化なし」と判定されて録画が途中終了する事象が発生した(`runs/th07_manual_runs/202607151859.mp4`, 実録画時間40.1秒)。

フェーズ13で設計した終了検知は、直前フレームとの平均絶対誤差(MAD)が閾値10.0を下回る状態が8回連続(16秒)したら終了とみなす方式である。

## 調査

該当動画をフレーム単位で確認したところ、40秒時点で映っていたのはリプレイ一覧画面等ではなく、ステージ序盤(スコアが継続的に増加中)の**霧のかかった川の背景**だった。この区間は敵弾がほとんど存在せず、背景も淡くぼやけているため、実際にプレイが進行しているにもかかわらず視覚的な変化に乏しい。

`POLL_INTERVAL_SEC`(2秒)と同じ間隔でフレームを抽出し、スクリプトと同じ処理(グレースケール化・160x120ダウンサンプル)でMADを計測した:

| 区間(秒) | MAD |
|---|---|
| 8→10 | 21.02 |
| 10→12 | 8.68 |
| 12→14 | 6.83 |
| 14→16 | 4.43 |
| 16→18 | 5.23 |
| 18→20 | 7.71 |
| 20→22 | 7.84 |
| 22→24 | 8.26 |
| 24→26 | 8.56 |
| 26→28 | 8.20 |
| 28→30 | 8.43 |
| 30→32 | 8.34 |
| 32→34 | 8.06 |
| 34→36 | 7.68 |
| 36→38 | 7.46 |
| 38→40 | 7.84 |

10秒以降、MADが旧閾値10.0を30秒以上連続して下回り続けており、`STILL_CONSECUTIVE_REQUIRED`(8回=16秒)の条件を満たして誤検知に至ったと判断した。

また、同じ区間で1フレーム(1/60秒)差のMADを測定したところ0.71であり、これはffmpegの再エンコード等に起因するノイズフロアの目安と考えられる。

フェーズ13の既存レポート(`reports/13_phase13_recording_quality_improvements.md`)を再確認すると、別リプレイ(th7_07相当)のゲームプレイ中最小MADは3.50と記録されており、今回の霧背景に限らず、旧閾値10.0はゲームプレイ中の揺らぎ幅に対してもともと余裕が乏しかったことがわかる。一方、同レポートでは実際のリプレイ終了(一覧画面復帰)時はMADが0.0近辺に張り付き続けることも確認されている。

## 対応

`STILL_MAD_THRESHOLD`を10.0から**2.0**に引き下げた。ノイズフロア(0.71)より十分高く、かつ実測されたゲームプレイ中最小値(3.50)より十分低いため、両者を分離できるマージンを確保している。`STILL_CONSECUTIVE_REQUIRED`(8回=16秒)は据え置き。

あわせて、`th7_09.rpy`の総再生時間が約30分であるのに対し、既定の`TIMEOUT_SEC`が22分に設定されていた点も是正した。仮に静止検知が機能しなくても30分の再生を録り切れるよう、22分から**40分**に拡大した。

## 未検証事項

- 今回の修正は過去の録画データの事後分析に基づくものであり、`th7_09.rpy`を新しい閾値で実際に最後まで録画できるかは未検証。次回実行時に確認が必要。
- 閾値2.0がより長時間・他ステージのリプレイでも安全か(逆に、真の終了を検知できずタイムアウトに頼ってしまうケースがないか)は、複数リプレイでの検証が望ましい。
