# GPUのeu-north-1フォールバックを本番で検証した（初回デプロイ直後）

- **検証日**: 2026-10-11（UTCでは10/10 20:05〜21:22）
- **対象**: GPUワーカーの容量不足時フォールバック（Issue #296、PR #311）。th06nc・th15・倍速録画（th07 2倍速）と、実ユーザーのジョブ1件
- **環境**: 本番。eu-north-1b の g6f.2xlarge（Spot）、AMI `ami-06257c9bafd920d3d`（eu-south-2 の `ami-08b3f94444612a932` のコピー）、ECRレプリカのGPUイメージ（`sha256:034627…`）
- **結論**: th06nc・th15（Extra）・2倍速は eu-north-1 で正常に録画できた。th15 の1面だけのリプレイだけはステージ終了時のWineクラッシュで失敗したが、リージョンではなく資産更新に伴うリプレイ固有の問題とみて #312 に切り出した

初回デプロイ（`deploy-sattori` skill §4）の直後に、管理設定 `forceGpuFallbackRegion` を有効にして、
GPUジョブを eu-north-1 で起動させた。検証中に実ユーザーのGPUジョブが eu-south-2 の容量不足で
**自動的に** eu-north-1 へ逃げて完走しており、強制なしのフォールバック経路も本番で動いた。

## 目的

AGENTS.md §3 の実機検証。同じAMI・同じインスタンスタイプでもリージョンが変われば録画品質が
変わりうるため、eu-north-1 で GPU 描画（DXVK の th06nc・wined3d の th15）と倍速録画が eu-south-2 と
同等に録画できるかを確かめる。あわせて、リージョンをまたぐ処理（緊急停止・コスト推定）を本番で確認する。

## 方法

`verify-recording-in-production` skill §5 の手順で、API を直接叩いてジョブを作り、1本ずつ流した
（eu-north-1 の G 系 Spot クォータが 8 vCPU で、同時に1台しか動かせないため）。リプレイは
`packages/replay-parser/test-fixtures/` のもの。結果は `GetJobResponse`、ワーカーログ（重複フレーム率・
OpenGL renderer）、出力動画（ffprobe と目視）で確認した。

### th15 の1面だけのリプレイのクラッシュ（#312）

`wine: Unhandled page fault on read access to 00000002 at address 0045D141` が3試行とも同じ位置
（Stage 1 ボス撃破後の会話シーン、リプレイ開始から約271秒）で起きた。同じリプレイは 2026-09-18 に
eu-south-2 で完走しており、その後 2026-10-02 に th15 のタイトル資産（MOD）が倍速録画対応で
更新されている。更新後に本番で録画された th15 は Extra Stage のリプレイだけで（すべて成功）、
途中の面で終わる本編リプレイは録画されていなかった。同じAMIのコピー・同じインスタンスタイプで
Extra Stage は eu-north-1 でも完走したので、リージョンが原因である可能性は低いと判断した。

### th07 2倍速のデシンク判定は誤判定

スコア監視の最終サンプルは 33,488,140 で、記録スコア 33,488,400 と一致するサンプルが無かった。
動画の末尾を見ると、スコアはボーダーボーナスの加算で 33,454,750 → 33,485,280 と上がり続け、
フェードアウト中に 33,488,400 に達していた。最後の上昇を取りこぼしただけで、
[`2026-10-03`](2026-10-03-speedup-production-e2e-reverification.md) の th08 と同じ既知のパターン
（等倍でも起きうる判定精度の問題）。

### リージョンをまたぐ処理

- **緊急停止**: `th15_01` のリトライを `POST /admin/jobs/{jobId}/stop` で止めた。CloudTrail で、
  `AdminStopJobFn` が **eu-north-1 に対して** `TerminateInstances` をエラー無しで呼んだこと、
  eu-south-2 への誤った呼び出しが無いことを確認した。
- **コスト推定**: 4ジョブとも、ワーカーが記録したサイズで転送料が計上された（推定値の混入なし）。

## 考察・既知の限界

- 各タイトル1本ずつの検証で、重複フレーム率も録画開始15〜45秒の30秒スポットだけを見ている
  （`known-limitations.md` §3）。尺は理論尺と+6秒以内（カットで残る選択画面のぶん）で一致した。
- フォールバックしたジョブでは、リージョン間転送料が Spot 代の2〜5倍になる。Issue #296 で見込んだ
  「1件約$0.05」とおおむね合う（長いリプレイと1080p出力では $0.08）。
- th15 の失敗がリージョンと無関係だという判断は状況証拠による。eu-south-2 の容量が戻ったら、同じ
  リプレイを eu-south-2 で流して確定させる（#312）。
- 初回デプロイで踏んだ手順の誤り（同じイメージの再pushではECRの複製が起きない・非対話の
  `cdk deploy` が承認待ちでスタックを飛ばす）は `deploy-sattori` skill に反映した。
