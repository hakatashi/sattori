# th20・th06ncのフレーム同期録画のEC2実機検証（Issue #390、親 #399）

- **検証日**: 2026-11-23
- **対象**: th20（1280x960）・th06nc（720p、D3D11・BC7展開のCPU描画）。判断は [`0081`](../decisions/0081-frame-sync-plan-for-th20-and-th06nc.md)
- **方法**: [th06〜th13の検証](2026-11-22-th06-to-th13-frame-sync-ec2-verification.md)と同じ。実験ジョブ（`POST /admin/experiments`）で、本番の完了済みジョブのリプレイを eu-south-2 の EC2 Spot（フレーム同期）で `c7i.2xlarge` と `c7i.4xlarge` で各1本録画した（計6本）。ワーカーイメージは `worker/Dockerfile` に全タイトルのMOD（フレーム同期対応）を焼き込み `SATTORI_MOD_DIR` で差し替えた検証用イメージ（`exp-framesync-th20-th06nc-1`）。本番のタイトル資産（S3）は変えていない
- **結論**: **6本すべて試行1回で完走**。三者照合（MODの書き出し＝動画＝音声）は th20 の2本で確認（端数0バイト）、理論尺は±0.6%以内、スコアは全6本で一致（`desyncDetected=false`）

- 6本とも `timedOut=false`、ワーカー内の試行は1回。th20 の三者照合は 112143 = 112143 = 112143（2xl）・112287 = 112287 = 112287（4xl）、いずれもPCM端数0B。
- **推定コストは th20 は `.4xlarge` が安く（th15と同じ）、th06nc は `.2xlarge` が安い**（640x480と同じ）。これが段の順序の根拠。
- th20 の `.2xlarge` は総所要が尺の1.68倍。`maxEstimatedDurationSeconds`（3300秒）の尺では約92分で、SFnの150分に収まる（th15の1.74倍と同程度）。配信用変換（1280x960→1440x1080、約3.5GB）が `.2xlarge` で約17分かかる。
- th06nc のExtra（Lunaticの高密度弾幕とは別）でも、実時間方式のCPU段で出ていた描画の間引き（0067）は、フレーム同期では原理的に起きない（遅くなるだけ）。

### 視聴

配信版（720p/1440x1080）から先頭・等間隔8点・終端の10フレームを抜いて確認（th06nc Normal 2xl・th06nc Extra 4xl・th20 Normal 4xl）。先頭はタイトル/リプレイ選択画面、ステージ1〜エンディング（th20は`STAGE CLEAR`、th06ncはExtra Phantomまで）が破綻なく続き、FPS表示は60。保存先: `/mnt/cache3/sattori-390-th20-th06nc/`（使い捨て）。聴感での音声確認はしていない。

## 段の `estimatedRealtimeFactor` に入れた値

上限解除後の速度を丸めて下げた値（EC2）。自宅は[#389のレポート](2026-11-22-worker-frame-sync-full-length-verification.md)の2並列の実測（th06nc 0.95倍・th20 0.63倍）を下げた値。

| 段 | th06nc | th20 |
| --- | --- | --- |
| 自宅 | 0.9 | 0.6 |
| `.2xlarge`帯 | 1.2 | 0.95 |
| `.4xlarge`帯 | 1.7 | 1.5 |

## 未確認

- GPU の段（実時間のth06nc 2倍速・th20 1倍速）は対象外（計画の最後の段）。
- 自宅ワーカー経由の本番での録画（デプロイ後に確かめる）。th20 の2並列ハング（#179）がフレーム同期の2並列で再現しないかは、#389で th20 を含む2並列を完走した以外には未確認。
- c7a・m7i の `.2xlarge` の速度（[`0078`](../decisions/0078-frame-sync-plan-and-instance-type-verification-policy.md)の方針で実測しない）。
- th06nc の1080p（保留のまま）。本番のタイトル資産（S3）のth20・th06ncのMODはフレーム同期対応前のまま。デプロイ前に差し替えが必要。
