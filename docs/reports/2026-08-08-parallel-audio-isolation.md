# ジョブ専用 PulseAudio sink による並列録画時の音声分離

- **検証日**: 2026-08-08
- **対象**: ジョブごとの PulseAudio null-sink（Issue #48、
  [`decisions/0013`](../decisions/0013-per-job-pulseaudio-sink.md)）
- **環境**: このリポジトリのローカル環境（開発マシン）
- **結論**: 2並列でも音声は混ざらない。単一ジョブの通し録画にもリグレッションなし

th07 と th08 を専用 sink 付きで同時録画し、片方を SIGSTOP で止める対照実験で混成が
起きていないことを確認した。併せて単一ジョブのフル尺録画でリグレッションが無いことも
確認している。手順は touhou-recorder reports/41 Task 3 と同じ。

## 目的

ジョブ専用 sink（`PULSE_SINK` でゲーム側の出力先を固定し、その monitor を録音側 ffmpeg の
入力にする方式）が、同一ホストでの並列録画時に音声を実際に分離できているかを確かめる。

## 方法

1. th07 と th08 を専用 sink 付きで同時に録画開始する。
2. `pactl list sink-inputs` で各ゲームが自分の sink にのみ接続していることを確認する。
3. th08 のプロセスを SIGSTOP で停止し、両者の sink monitor の音量を測る（対照実験）。
4. 別途、単一ジョブ（th06、`th6_03.rpy`）の通し録画（379秒）を実施する。

## 結果

| 対象 | 測定値 | 測定条件 |
| --- | --- | --- |
| 停止中の th08 側 sink の monitor | `mean_volume: -91.0 dB`（実質無音） | SIGSTOP 中 |
| 動作中の th07 側 sink の monitor | `-8.1 dB` | 同時刻 |
| 単一ジョブ（th06）の重複フレーム率 | 0.3% | 録画開始15〜45秒の30秒スポット |
| 単一ジョブ（th06）の音声トラック | あり（mean -10.3 dB） | 通し録画379秒 |
| 単一ジョブ（th06）の A/V 同期ズレ | -0.045 秒 | 実測 |

終了検知・sink の破棄とも正常に動作した。

## 考察・既知の限界

A/V 同期の実測ズレ -0.045 秒は、`auto_null` 共有時にローカルで観測されていた 0.6〜1.4 秒
より小さい（専用 sink ではゲームの音声ストリームが既に流れている状態で録音 ffmpeg を
開始するためと考えられる、touhou-recorder reports/41 §4）。いずれにせよ実測ベースの
`-itsoffset` 補正が値によらず吸収するため、この差自体は問題にならない。

重複フレーム率は録画開始15〜45秒の30秒スポットしか見ていない（Issue #93）ので、通し録画
全編の代表値ではない。また本検証はローカル環境のみで、EC2 での並列実行は対象外
（EC2 Fleet は1インスタンス=1ジョブのため並列は起こらない）。自宅サーバーでの並列録画の
品質そのものは [`2026-08-09-home-worker-parallel-recording.md`](2026-08-09-home-worker-parallel-recording.md)
で別途測っている。
