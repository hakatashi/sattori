# th13・th14 のスペルカード名をゲームアセット(ECL)から抽出する

- **検証日**: 2026-11-28
- **対象**: th13(東方神霊廟)・th14(東方輝針城)の `thNN.dat` 内のステージ別 ECL(`stNN*.ecl`)。
  リプレイパーサのスペルカード名テーブル(`packages/replay-parser/src/data/th13|th14/spellcards.json`)の裏取り
- **環境**: 自宅ワーカー機。タイトル資産(`th14-assets.tar.gz`、th13 は展開済みのもの)の `thNN.dat` を、THA1 形式の
  自作展開スクリプト(Python)で展開。ゲームは起動していない
- **結論**: **ECL のスペルカード名はローリング XOR(初期鍵 0x77・増分 7・増分の増分 16)でマスクされているだけで、
  th13・th14 とも全名前を復号できる。** 画面から書き起こした名前と、th13 は67種・th14 は61種が両方向で完全一致した。
  番号と難易度の対応は ECL からは取れず、Player Data 画面と東方Wiki で裏取りした

th13 のスペルカード名の実装時は「名前は `th13.exe` にも ECL にも平文・1バイト XOR では入っておらず、アセットから
取れない」と結論して画面から書き起こした。これは1バイト XOR しか試していなかったための誤りで、本検証で訂正する。
今後 th15 以降(th15・th20・th128 は番号体系も違う)で名前テーブルが要るときは、まず同じ手順で ECL から復号を試すこと。

## 1. 目的

th14 のスペルプラクティスにも、th06nc・th13 と同様に名前を出したい。画面からの書き起こしは誤字が混ざりうる
(th13 では「符蝶」→「符牒」、「猯符」→「狢符」などの修正が後から要った)ので、ゲーム自身のデータから取れないかを調べる。

## 2. 方法

1. `th14.exe` に Shift-JIS の平文で名前が入っていないか確認 → なし。
2. `th14.dat` を展開(THA1: ヘッダ・ファイル表・各ファイルのブロック暗号 + LZSS)。`default.ecl` と `st01`〜`st07` 系の ECL(th14 は 22本、th13 は 21本)が出る。
3. 既知の名前(「テイルフィンスラップ」)を Shift-JIS にし、全 ECL のあらゆるオフセットで
   「暗号文 ⊕ 平文」の鍵列を計算。**隣接差が一定**(1次)、または**差の差が一定**(2次)になる箇所を探す → 2次一定
   (鍵列 145, 248, 111…、差 103→119→135…、差の差 16)が1箇所ヒット。
4. そこから先頭へ逆算して、名前の開始位置での初期鍵 **0x77**、初期増分 **7**、増分の増分 **16** を得る。
   ```python
   def dec(b, k=0x77, s=7, s2=16):
       o = bytearray()
       for c in b:
           o.append(c ^ k); k = (k + s) & 255; s = (s + s2) & 255
       return bytes(o)
   ```
5. 全 ECL の全オフセットを `dec` で復号し、「Shift-JIS として読め、`「…」` で終わり、NUL 終端、制御文字なし」の
   文字列を名前として収集。スペルカード名のオペランドは直前に `20 a1 07 00` + 長さ(4バイト)が付く。
6. 収集結果を、画面から書き起こした名前集合と突き合わせる。th13 は既存の `spellcards.json` と、th14 は
   スクリーンショット14枚から作った表と比較。
7. th14 の番号・難易度の対応は、東方Wiki 英語版(`Double Dealing Character/Spell Cards/Stage_1〜6, Extra`、
   ゲームの通し番号 No.001〜120 付き)と全件突き合わせた。

## 3. 結果

| ゲーム | ECL から復号した名前(重複除く) | 画面の表の名前(重複除く) | 差 |
| --- | --- | --- | --- |
| th13 | 67 | 67 | 0(デコーダに `cp932` を使った場合。下記注) |
| th14 | 61 | 61(120エントリ=番号×難易度) | 0 |

- 復号できるのは**名前の文字列だけ**。番号(No.)・難易度との対応は ECL の構造からは得られない
  (同じ名前が難易度違いで複数のスペルから参照されるため)。
- th13 の Overdrive(No.120〜127 の8件)の名前も ECL に入っていた。
- th14 の番号体系は難易度ごとの通し番号(Hard=1,5,9…・Lunatic=2,6,10…・Easy=3,7,11…・Normal=4,8,12…が基本。
  No.1〜2 の氷符と No.27〜28 の牙符は Hard/Lunatic のみ、No.109〜120 が Extra)。東方Wiki の一覧と120件すべて一致。
- **注: デコーダは `cp932` にすること**。Python の `sjis` は 0x8160 を U+301C(〜)、`cp932` は U+FF5E(～)に
  するため、th13 の「道符「ＴＡＯ胎動　～道～」」だけ `sjis` では1件ずれる(ゲームも日本語 Windows の cp932 で表示する)。
  th14 の抽出は `sjis` で行ったが、この文字は th14 にない。

## 4. 考察・既知の限界

- 確認できたのは **th13 と th14**。THA1 形式・同じ鍵が他タイトル(th10〜th12・th15 以降)の ECL にも使えるかは
  未確認(th15 以降は ECL の構造・暗号が変わっている可能性がある)。
- 総当たりは**既知の名前が1つ要る**。未知のタイトルでは、まず画面から1件だけ書き起こして鍵を求めるか、
  上記の鍵が使えるか直接試すのが早い。
- `dec` による走査は、名前以外の ECL 内容も復号するので、フィルタ(`「…」` で終わる・制御文字なし)に漏れる名前
  (括弧を持たない名前など)が出る可能性がある。今回の両タイトルでは漏れは見つからなかった。
- 本検証で得た結論の反映: th14 のスペルカード名テーブルを新設(`src/data/th14/spellcards.json`)。th13 は
  既存テーブルが ECL と一致したため変更なし。
