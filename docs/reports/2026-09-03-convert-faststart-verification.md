# 配信用変換への`-movflags +faststart`追加(Issue #90)の検証

- **検証日**: 2026-09-03
- **対象**: `worker/convert.py`の`build_convert_cmd()`に`-movflags +faststart`を追加した際の、変換時間・moov atom位置・A/V同期・尺への影響
- **環境**: ローカルマシン(HakataMatrix)、ffmpeg 6.1.1
- **結論**: moov atomは先頭(ftyp直後)へ移動し、変換時間の増分は誤差範囲(実測で有意な増加なし)。映像・音声のデコード結果はfaststart無しの出力と完全一致し、尺・A/V同期に影響なし。

実機(EC2/自宅ワーカー)ではなくローカルでの疑似データによるスモークテスト。ただし
`-movflags +faststart`はmux処理のみでエンコード自体には関与しないオプションのため、
CPU差はあっても定性的な結論(位置移動・内容不変)は実機でも変わらない。

## 目的

Issue #90の「やること」のうち、変換時間の実測とA/V同期・尺の不変性のスモークテスト確認。

## 方法

1. th06/07/08/11相当(640x480・等倍・2本出力)を想定し、`ffmpeg -f lavfi testsrc/sine`で
   640x480・60fps・10分(600秒)の疑似生録画データを生成
   (`-c:v libx264 -preset veryfast -crf 18` — `recording/ffmpeg.py`の録画時設定と同一)。
2. `convert.build_convert_cmd()`で実際の変換コマンドを生成し(720pへのアップスケールを含む)、
   それをそのまま実行した場合(`+faststart`あり)と、コマンドから`-movflags +faststart`だけを
   除いた場合(旧挙動相当)を同一入力に対して実行して比較。
3. 変換時間を`time.monotonic()`で計測。
4. 出力ファイルのトップレベルMP4ボックスをPythonで手書きパースし、`moov`と`mdat`の順序を確認。
5. `ffprobe`で両者の尺・解像度・フレームレート・サンプルレートを比較。
6. `ffmpeg`で両者を再デコードし(`-f rawvideo`/`-f s16le`)、映像・音声それぞれのMD5が一致するかを確認(mux構造以外に差が無いことの確認)。

## 結果

| 項目 | faststartなし(旧) | faststartあり(新) |
| --- | --- | --- |
| 変換時間(10分素材1回, 640x480→960x720) | 45.09s | 44.24s(旧比 -1.9%、誤差範囲) |
| トップレベルボックス順序 | `ftyp, free, mdat, moov` | `ftyp, moov, free, mdat` |
| 出力ファイルサイズ | 27,588,699 bytes | 27,588,699 bytes(完全一致) |
| 尺(`ffprobe` duration) | 600.000000s | 600.000000s |
| 映像解像度/fps | 960x720 / 60fps | 960x720 / 60fps |
| 音声サンプルレート | 44100Hz | 44100Hz |
| 映像デコードMD5(`-f rawvideo`) | `f647aa5f...` | `f647aa5f...`(一致) |
| 音声デコードMD5(`-f s16le`) | `47e33d1c...` | `47e33d1c...`(一致) |

## 考察・既知の限界

- 10分・640x480の1本のみでの計測であり、Issueが想定する「30分・約1GiB」相当の素材や
  th20(1280x960)・低速録画(音声リサンプルあり)のケースでは未計測。ただし`+faststart`は
  最終的なmux段階でのみ効くオプションであり、フィルタグラフ(スケーリング・オーバーレイ・
  音声リサンプル)には関与しないため、これらのケースでも変換時間・内容への影響の定性的な
  結論(無視できる増分・内容不変)は変わらないと考えられる。
- 変換時間はローカルマシンでの1回計測であり、EC2上での実測(CPU世代・vCPU数の違い)ではない。
  ただしfaststartが追加するのは「エンコード完了後にmoovを書き直して先頭へ移動する」という
  ほぼI/Oバウンドな追加パスであり、CPUバウンドなエンコード時間そのものへの影響は環境に
  依らず小さいと考えられる。
- ブラウザでのストリーミング再生開始レイテンシ・CloudFront配信量そのものの改善効果は、
  本検証ではmoov位置の移動という間接的な指標でのみ確認しており、実際のブラウザでの
  Range挙動は未検証。
