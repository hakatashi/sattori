# th06nc ver 1.0.6 アップデートのリプレイ互換性とMOD動作のローカル検証

- **検証日**: 2026-09-28
- **対象**: th06nc（東方紅魔郷: New Classic）ver 1.0.6（2026-09-25配信）のゲームデータ。
  旧版で記録したリプレイ・新版で記録したリプレイの解析と再生、MODのスコア監視
- **環境**: HakataMatrix（自宅ワーカー機、AMD Radeon VII、`sattori-home-worker`停止中）。
  GPUを渡さないDockerコンテナ（`sattori-worker-gpu`イメージ+Xvfb）、wined3d+llvmpipe
- **結論**: リプレイ形式は不変で、旧版・新版どちらのリプレイも新版で最後まで再生でき
  記録スコアと一致した。**ただしexeの再ビルドでMODのスコアRVAが移動しており
  （`0x004F2798`→`0x0053D3E8`）、未修正のままだと全ジョブでデシンクを誤検知する**。
  Steam版の正規`steam_api64.dll`もゲームデータに戻っていた。

GPU描画・DXVKでの録画品質（fps・重複フレーム率）はこの環境では検証できないため、
本番（g6f.xlarge）での録画確認は別途必要。

## 目的

ゲーム側の公式アップデートでゲームデータを差し替えても録画パイプラインが壊れないこと、
特に（1）リプレイ形式の互換、（2）旧版リプレイの新版での再生互換、（3）MODが使う
スコアRVA・メニュー操作シーケンスが変わっていないことを確認する。

## 方法

1. 新旧ゲームデータ（`worker/games/th06nc`・`th06nc.old`）の差分確認（`diff -rq`・`md5sum`・PEセクション表）。
2. 新版で記録した`packages/replay-parser/test-fixtures/th06nc/th6_33.rpy`（Extra・霊夢A・
   20020フレーム・記録スコア52,476,730）をパーサーで解析。
3. 新版ゲームデータ（`steam_api64.dll`はth06nc用スタブで上書き）で次の2本を
   `record_th06nc.py`により再生・録画し、`--expected-score`でスコア一致を判定。
   - 旧版リプレイ: `worker/tests/fixtures/mod-integration/th06nc/th6_31.rpy`（Extra・7601フレーム・25,890,400）
   - 新版リプレイ: 上記`th6_33.rpy`
4. 実行条件: `/dev/dri`を渡さないコンテナ、`TH06NC_TIME_SCALE=7`、`LIBGL_ALWAYS_SOFTWARE=1`、
   `dxvk_dll_overrides`を`d3d11,dxgi,d3d10core=b`へ書き換え（wined3d）、
   `--max-attempts 1 --max-duplicate-rate 100`。手順は`verify-game-update` skill。

## 結果

| 項目 | 結果 |
| --- | --- |
| リプレイ形式（0x04の`u16`） | 旧版と同じ`0x010f`。パース成功、Extra開始時power=0も旧版フィクスチャ（th6_02）と同傾向 |
| ゲームデータの差分 | `th06nc.exe`・`th06CM/ED/TL.dat`・`steam_api64.dll`（**正規版に戻っていた**）が変化 |
| 起動・起動ダイアログ | 起動成功、ダイアログ無し（従来どおり） |
| メニュー操作シーケンス（Down固定3回） | 両リプレイとも`sequence complete`まで完走 |
| 旧版リプレイ × 新版（旧RVAのMOD） | 最後まで再生（録画1029秒）。**ScoreMonitorは最後まで0**、デシンク誤検知 |
| 旧版リプレイ × 新版（メモリ直接読み、新RVA） | 内部値が記録スコア25,890,400に一致 |
| 新版リプレイ × 新版（修正版MOD） | 最後まで再生（録画2520秒）。記録スコア52,476,730と一致（`desyncDetected: false`） |

- スコアRVA: 新版は内部値`0x0053D3E8`・表示値`0x0053D3E0`（内部値の8バイト手前に表示値が
  ある関係は旧版と同じ）。`.data`セクションが`0x323000`→`0x36d000`へ移動しており、
  セクション内オフセットも`0x1CF798`→`0x1D03E8`とずれているため単純な平行移動ではない。
  特定は再生中プロセスの`/proc/<pid>/mem`をホストから2回読み、増加したu32を列挙して行った。
- 録画のfpsは約7〜10fps（ソフトウェア描画）のため重複フレーム率は93%で、品質の評価には使えない。

### 対照実験: DXVK+lavapipeでは起動しない（環境要因）

当初DXVK（lavapipe、Vulkanのソフトウェア実装）で実行したところ、新版exeは起動直後に
`Unhandled division by zero`（DXVKのDXGI初期化直後）で落ちた。旧版exeでも同じアドレス
オフセットで同じように落ちたため、アップデートとは無関係の検証環境側の制約と判断し、
wined3dへ切り替えた。

## 考察・既知の限界

- 本番で使うGPU+DXVKの描画経路・60fpsでの重複フレーム率・1080p録画は未検証。
  資産アップロード後に本番で1本録画して確認すること。
- 旧版で記録したリプレイは1本（Extra）、新版は1本（Extra）のみ。通常ステージ・
  スペルプラクティス・Challengeモードの再生互換は未確認。
- 新版リプレイを旧版exeで再生する（逆方向の互換）は確認していない。本番は新版のみを使う
  ため不要と判断した。
