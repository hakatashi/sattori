# AWSリージョン移行のコスト検討レポート

**調査日**: 2026-07-27
**対象**: Sattori 本番環境（現在 `us-east-1`）
**目的**: EC2 Spot価格の全リージョン比較を起点に、プロジェクト全体を他リージョンへ
移設することが現実的か・コスト的に有利かを具体的な数値で判断する
**カバー範囲**: オプトイン済み18リージョン（実測）＋ 未オプトイン16リージョン（推計）＝
**AWS商用34リージョン全件**

---

## 追記（2026-08-03）: 移設を実施することにした

本レポート §0・§8 は「移設は推奨しない」「`eu-south-2`は実質的に候補外」
「もし将来どうしても移すなら`us-east-2`一択」と結論していたが、以下の理由から
**この結論を撤回し、`eu-south-2`への移設を実施した**（`apps/api/README.md`
「EC2 Fleet インスタンスタイプの分散配置」・
[`decisions/0016`](../decisions/0016-ec2-fleet-instance-type-diversification.md)・`infra/README.md`参照）。

1. **§7.2で最大のリスクとされていた「録画品質の再検証」が解消した**。
   touhou-recorder `reports/42`（2026-07-31）がeu-south-2実機でth06/07/08/11
   すべてのフル尺録画を行い、重複フレーム率がus-east-1のベースラインと同等か
   それ以上に良好（0.1%/0.2%/0.2%/4.5%）であることを確認した。
2. **§7.3の「SESが実質的なブロッカー」という評価を採らなかった**。SESクライアント
   だけus-east-1に向ける構成（`apps/api/src/ses.ts`の`SES_REGION`環境変数）は、
   本レポート自身が510-519行目で「絶対的なブロッカーではない」と述べている
   回避策そのものであり、実装コストは小さい。ドメイン検証・DKIM・サンドボックス
   解除もus-east-1のものをそのまま使い続けられる。
3. **本サービスは正式リリース前であり、インフラの大きな移動を行うならリリース前が
   最適なタイミング**という判断を、§8.3の「年$231の節約では検証工数に見合わない」
   という結論より優先した。リリース後の同一移設は、本番トラフィック・ユーザー影響・
   既存データ移行のコストが追加でかかる。

一方で、本レポートが指摘した以下の懸念は**解消されておらず、既知のトレードオフとして
受け入れた**:

- **Spotキャパシティプール数の後退**（§2、eu-south-2は`.xlarge`9プール/3タイプ、
  `.2xlarge`6プール/2タイプで、us-east-1の30/6・20/4を大きく下回る）。
  `apps/api/src/ec2.ts`の候補リストをeu-south-2で提供される`c7i`/`c7a`/`c7i-flex`
  へ絞った上でも、プール数はus-east-1の半分以下に留まる。移設後は起動失敗率
  （`InsufficientInstanceCapacity`によるリトライ発生率）を監視すること。
- **§6の「削るべきはリージョンではなく動画サイズ」という指摘は今回の移設でも解消
  していない**。CloudFront無料枠(1TB/月)の消化率は移設前後で変わらないため、
  動画ビットレート見直し（`-crf 18`→`20〜22`）は依然として優先度の高い残課題。
- `c7a.xlarge`/`c7i-flex.xlarge`/`c7a.2xlarge`はeu-south-2実機での検証が
  まだ済んでいない（us-east-1では検証済み、または未検証）。本番トラフィックの
  主力は実機検証済みの`c7i.xlarge`/`c7i.2xlarge`とし、他は起動失敗耐性確保の
  ための暫定候補として扱う。

以下は移設前（2026-07-27時点）に行った調査の原文であり、歴史的な記録として残す。

## 0. 結論（先出し、2026-07-27時点。上記2026-08-03の追記で判断を更新済み）

**移設は推奨しない。ただし「us-east-1が最安」という前提は誤りであり、その事実は
記録しておく価値がある。**

- 現行の `us-east-1` は、Spot価格で見ると実測18リージョン中 **7位**。最安の
  `eu-south-2`（スペイン）より **24〜35%高い**。
- ただし **`eu-south-2` は SES が提供されていない**（AWS公式のSESエンドポイント一覧に
  存在しない）。マジックリンクと完了メールに SES を使う現行アーキテクチャでは、
  最安リージョンはそのままでは採用できない（§7.3）。
- **未オプトインの16リージョンも推計で全件比較したが、移設先として有力なものはない**
  （§2.3）。最有力の `eu-south-1`（ミラノ）ですら候補インスタンスタイプが
  `.xlarge` で2種・`.2xlarge` で1種しかなく、Issue #29 で確保した起動失敗耐性が
  壊滅する。
- しかし月1000録画時の**総コストは `us-east-1` で約 $56/月**にすぎず、最も有利な
  リージョンへ移しても**節約額は月 $5〜14（年 $56〜165）**にとどまる。
- 一方で移設には **SESの本番アクセス再申請（リージョン単位）・DKIM DNS再設定・
  ACM証明書のus-east-1固定に伴うクロスリージョンスタック化・ECR/タイトル資産の
  再アップロード・そして最大のリスクである「新しいSpotプールでの録画品質の
  再検証」** が伴う。touhou-recorder `reports/27`・`reports/40` が示す通り、
  このプロジェクトではインスタンス選択が録画品質に直結するため、リージョン移設は
  実質的に「品質検証のやり直し」を意味する。
- **年 $56〜165 の節約のためにこのリスクを取る合理性はない。**
- コスト削減の実際のレバレッジは**リージョンではなく動画サイズ**にある（§6）。
  現状 720p版の平均が 1,036 MiB で、月1000ダウンロードで CloudFront 無料枠
  1TB/月をほぼ使い切る（0.99TB）。ここを超えると **$0.085〜0.114/GB** が発生し、
  リージョン差など一瞬で吹き飛ぶ。

## 1. 調査方法

### 1.1 Spot価格

`aws ec2 describe-spot-price-history` で、**オプトイン不要＋本アカウントでオプトイン
済みの全18リージョン**について、対象インスタンスタイプの**直近30日分の全価格変更
イベント**を取得した（2026-06-27〜2026-07-27）。

対象タイプは `apps/api/src/ec2.ts` の候補リストに準拠:

| 用途 | インスタンスタイプ |
| --- | --- |
| th06/07/08（`DEFAULT_CANDIDATE_INSTANCE_TYPES`） | `c7i.xlarge` / `c7a.xlarge` / `c6a.xlarge` / `c6i.xlarge` / `c7i-flex.xlarge` / `c5a.xlarge` |
| th11（`TH11_CANDIDATE_INSTANCE_TYPES`） | `c6i.2xlarge` / `c6a.2xlarge` / `c7i.2xlarge` / `c7a.2xlarge` |

価格は**単純平均ではなく時間重み付き平均（TWA）**で集計した。Spot価格履歴は
「価格が変わった瞬間のイベント列」であり、単純平均を取ると短時間しか続かなかった
価格が過大評価されるため、各イベントを次のイベントまで前方補完して滞留時間で
重み付けしている。

集計単位は **(リージョン, インスタンスタイプ, AZ) = 1 Spotキャパシティプール**。
`CreateFleet` は `AllocationStrategy: price-capacity-optimized` で
「サブネット × 候補タイプ」の全組み合わせから選ぶため、リージョンの実効価格は
**最安プールの価格に近いが、価格だけでなく空き容量も加味される**。そこで
「最安プール（楽観値）」と「安価上位3プールの平均（実効値の推定）」の両方を出し、
以降のコスト試算には後者を使う。

### 1.2 その他のAWS料金

`aws pricing get-products`（AWS Price List API）で、S3 Standard・EBS gp3・
DynamoDB オンデマンド・パブリックIPv4 の各リージョン単価を取得。CloudFront は
公式料金ページで課金モデルを確認した。

### 1.3 稼働実績（前提値の根拠）

本番の DynamoDB `JobsTable` と出力S3バケットの実データから算出した。

| 項目 | 実測値 | 試算に使う値 |
| --- | --- | --- |
| 1ジョブの所要時間（`createdAt`→`updatedAt`） | 完走ジョブで 14〜66分、フルラン中心値 ≒ 35分 | **0.60時間** |
| リトライ・Spot中断による割増 | — | **×1.10** |
| 出力動画サイズ（元解像度） | 平均 694 MiB | — |
| 出力動画サイズ（720p） | 平均 1,036 MiB | — |
| 1ジョブあたり出力合計 | **1.69 GiB** | 同左 |
| 出力S3の平均保管量（7日ライフサイクル） | — | **394 GB-Mo** |
| ルートEBS（ECS最適化AL2023 AMI既定 gp3） | 30 GiB | 同左 |

**観察**

1. **`us-east-1` は最安ではない**。ユーザーの直感（us-east-2 のほうが安い）は正しく、
   `.xlarge` で **-11.8%**、`.2xlarge` で **-10.3%** の差がある。
2. `us-east-1` の強みは価格ではなく **プール数（30/6・20/4 で全リージョン中最多）**。
   これは 5AZ × 全候補タイプが揃うためで、Issue #29 が狙った起動失敗耐性という
   意味では最良のリージョンである。
3. `eu-south-2` は突出して安い（`.xlarge` で us-east-1 比 -35%）。ただし
   `c6a`/`c6i`/`c5a` 系が一切なく、`.2xlarge` に至っては `c7i`/`c7a` の2タイプしか
   選べない。安さは需要の低さの裏返しであり、**候補プールの薄さと表裏一体**。
4. 東京 `ap-northeast-1` は us-east-1 比 **+34%**（`.xlarge`）。日本のユーザーに
   近づけるという理由でも、コスト的には最悪クラスの選択になる。

### 2.2 Spot中断頻度（Spot Instance Advisor）

価格だけで選ぶと中断が増えてリトライコスト・所要時間が増える。AWS公式の
Spot Instance Advisor データ（`spot-bid-advisor.s3.amazonaws.com`）から、
各リージョンで**最も中断されにくい候補タイプの中断頻度**を抜き出した。

| リージョン | .xlarge 最良 | .2xlarge 最良 |
| --- | --- | --- |
| us-east-1 (現行) | `<5%` (c7i-flex, c5a) | **`5-10%`** (c6a.2xl, c7a.2xl) |
| us-east-2 | `<5%` (c7i-flex, c5a) | `10-15%` (c6a.2xl) |
| us-west-2 | `<5%` (c7i-flex, c5a) | `15-20%` |
| eu-north-1 | `<5%` (c7i-flex, c5a) | `10-15%` (c7i.2xl) |
| ap-south-1 | `<5%` (c7i-flex, c5a) | `5-10%` (c6a.2xl) |
| ap-northeast-2 | `<5%` (c7i-flex) | `10-15%` (c6i.2xl) |
| eu-south-2 | `<5%` (c7i-flex) | `<5%` (c7i.2xl) |
| ap-northeast-1 | `<5%` (c6a, c7i-flex, c5a) | `<5%` (c6a.2xl) |
| sa-east-1 | `5-10%` (c5a) | `>20%` |

`.xlarge` はどこでも `<5%` のタイプが確保でき差がつかない。**差が出るのは th11 の
`.2xlarge` 帯**で、`us-east-1` の `5-10%` に対し `us-west-2` は `15-20%` と明確に劣る。
中断は 60分タイムアウトの Step Functions リトライを誘発し、**課金時間を丸ごと1回分
無駄にする**ため、実効コストは表の価格差より us-west-2 に不利に働く。

なお `GetSpotPlacementScores`（target=1）は主要15リージョンすべてで最高スコア9を
返した。**1台単位の起動という本プロジェクトの使い方では、どのリージョンでも容量は
足りている**ことを意味する。

### 2.3 未オプトインの16リージョン（推計）

§2 までは本アカウントで有効な18リージョンの**実測値**である。未オプトインの
リージョンには `describe-spot-price-history` を発行できない（`AuthFailure` になる）
ため、別の手段で推計した。

#### 推計方法

**推計Spot価格 = オンデマンド価格 × (1 − Spot Instance Advisor の節約率)**

- オンデマンド価格は AWS Price List API（`aws pricing get-products`）から取得。
  これは **us-east-1 のエンドポイントから全リージョン分を取得できる**ため、
  オプトインの有無に関係なく参照できる。
- 節約率と中断頻度は AWS 公式の Spot Instance Advisor 公開データ
  （`spot-bid-advisor.s3.amazonaws.com/spot-advisor-data.json`）から取得。
  こちらも**商用34リージョン全件**を含む。

#### 推計精度の検証

同じ推計をオプトイン済み18リージョンに適用し、実測値と突き合わせた（`.xlarge`、
安価上位3タイプ平均）。

| 指標 | 値 |
| --- | --- |
| 誤差の中央値 | **−3.1%** |
| 誤差の平均 | +1.7% |
| 誤差の範囲 | **−45.8%（eu-south-2）〜 +30.5%（ap-northeast-2）** |

**中央値では十分実用的だが、個別リージョンでは大きく外れうる。** Spot Instance
Advisor の節約率はリージョン×タイプ単位の代表値であり、AZ単位の最安プールを
捉えられないためである。特に `eu-south-2` は実測 $0.0424 に対し推計 $0.0230 と
大幅に過小評価された。したがって**以下の推計値は「桁とおおよその順位」を見るもの
であり、±30%程度の幅があるものとして扱うこと。**

| eu-central-2 (チューリッヒ) | 0.0971 | 2 | 0.1837 | 1 | $97.42 | +$29.24 | `10-15%` | `10-15%` | あり |
| ap-east-2 (台湾) | 0.1149 | 3 | 0.2405 | 2 | $113.04 | +$44.86 | `<5%` | `<5%` | **なし** |

（比較基準の us-east-1 は §5.2 の $68.18）

#### 結論: 未オプトインリージョンに有力候補はない

1. **候補インスタンスタイプが決定的に不足している。** 16リージョン中、`.xlarge`
   候補6種のうち4種以上を提供するのは `ap-east-1`（5種）と `af-south-1`（4種）の
   2つだけ。**`.2xlarge`（th11用）に至っては、3種提供するのが `ap-south-2` と
   `ap-east-1` のみで、残り14リージョンは1〜2種しかない。** `ca-west-1` /
   `ap-southeast-4` / `il-central-1` は `.xlarge` も `.2xlarge` も**1種のみ**で、
   Issue #29 以前（`c7i.xlarge` 単独）より悪い状態に戻ることになる。
2. **最安に見える `eu-south-1`（ミラノ）も同じ罠。** 月 $13.71 の節約に見えるが、
   `.xlarge` は `c6i`/`c5a` の2種のみ、`.2xlarge` は `c6i.2xlarge` の1種のみ。
   さらに推計誤差 ±30% を考えれば、実測すれば us-east-1 と大差ない可能性もある。
3. **6リージョンは SES 非提供**（`ap-east-1` / `mx-central-1` / `ap-east-2` /
   `ap-southeast-6` / `ap-southeast-7`、およびオプトイン済みだが `eu-south-2`）。
4. **オプトインリージョン共通の運用上の不利**: アカウント単位の明示的な有効化が必要、
   新サービス・新インスタンスタイプの提供が遅れる、無効化にも時間がかかる。
   提供サービス数を SSM の
   `/aws/service/global-infrastructure/regions/<region>/services` で数えると、
   us-east-1 の **389** に対し `mx-central-1` は **147**、`ap-south-2` は **182** と
   半分以下である。

**→ 未オプトインリージョンは、オプトイン済みの上位候補（us-east-2 等）を上回る
メリットがない。** 唯一「実測してみる価値がわずかにある」のは `eu-south-1` だが、
`.2xlarge` が1種しかない時点で th11 の運用に耐えないため、実質的に候補外である。

## 4. リージョンに依存しないコスト（＝移設しても変わらない部分）

これが移設判断で決定的に重要である。

### 4.1 CloudFront — 完全にリージョン非依存

- **オリジンフェッチ（S3 → CloudFront）は、オリジンがどのAWSリージョンにあっても
  無料**。「Data transfer between CloudFront and your AWS origins is automatically
  waived when serving traffic through CloudFront」
- **インターネットへの転送料金はエッジロケーション（＝視聴者の地理）で決まり、
  オリジンリージョンとは無関係**。北米/欧州 $0.085/GB、日本 $0.114/GB、
  アジア太平洋 $0.120/GB（いずれも無料枠超過後の最初の9TB帯）
- **常時無料枠 1TB/月 + 1,000万リクエスト/月**（12ヶ月限定ではなく Always Free）は
  現在も有効

→ **本サービスで最大の変動費になり得る動画配信のコストは、リージョンを変えても
1円も変わらない。**

### 4.2 その他

- Lambda / SES / Step Functions / CloudWatch Logs は合計しても月 $2 程度で、
  リージョン差は ±10% 未満（＝月 $0.2 未満の差）。
- S3 リクエスト料金、ECR ストレージ（イメージ1本）、DynamoDB ストレージも同様に
  無視できる。

## 6. コスト構造の実態：削るべきはリージョンではない

月1000録画時の内訳（us-east-1, th11 25%想定, 合計 $68.18）:

| 項目 | 金額 | 比率 |
| --- | ---: | ---: |
| EC2 Spot | $51.58 | 76% |
| S3 出力保管 | $9.13 | 13% |
| パブリックIPv4 | $3.30 | 5% |
| EBS gp3 | $2.17 | 3% |
| その他 | $2.00 | 3% |
| **CloudFront** | **$0.00** | **0%（無料枠内）** |

**ただし CloudFront の $0 は薄氷の上に成り立っている。**

- 720p版の平均サイズは **1,036 MiB**。月1000ダウンロードで **0.99 TB** となり、
  常時無料枠 1TB/月 を **ほぼ使い切る**。
- 元解像度版も併せてダウンロードされたり、月1100録画に増えたりした時点で超過が
  始まる。超過分は北米エッジで $0.085/GB、**日本のエッジなら $0.114/GB**。
- 月2000録画（720pのみDL）なら約 2.0TB → 超過1.0TB → **月 $85〜114**。
  これはリージョン移設で削れる月 $5〜19 の **5〜20倍**である。

**コスト削減の優先順位**

| 施策 | 削減効果（月1000録画） | 実装リスク |
| --- | ---: | --- |
| 動画ビットレートの見直し（現状 `-crf 18 -preset veryfast`） | 数十%のサイズ減 → CloudFront超過を先送り、S3も比例減 | 低（品質とのトレードオフのみ） |
| 元解像度版の配信をやめる/期限短縮 | S3 保管を最大 -40%（$3.6/月） | 低 |
| S3 ライフサイクルを7日→3日に短縮 | S3 -57%（$5.2/月） | 中（ユーザー体験に直結） |
| **リージョン移設（us-east-2）** | **$5.76/月** | **高（§7）** |

`-crf 18` は視覚的にほぼロスレスな設定であり、`-crf 20〜22` へ落とすだけで
ファイルサイズは大きく下がる。**リージョン移設1回分の労力を crf 調整とその品質
確認に振り向けるほうが、確実に効果が大きい。**

## 7. 移設の実務コストとリスク

仮に `us-east-2` へ移すとした場合に必要な作業。

### 7.1 技術的にブロッカーにはならないが手間がかかるもの

| 項目 | 内容 |
| --- | --- |
| ACM 証明書 | `sattori.hakatashi.com` の CloudFront 用証明書は **us-east-1 必須**（詳細は §7.1.1）。本体を us-east-2 に移す場合、証明書だけ us-east-1 に残すクロスリージョン構成（`crossRegionReferences` か別スタック）が必要になり、CDK が確実に複雑化する |
| SES | **本番アクセス（サンドボックス解除）はリージョン単位**。us-east-2 で再申請が必要（通常24時間以内に回答）。加えて DKIM CNAME 3本を新リージョン用の値に差し替える DNS 作業が発生し、切り替え中はメール送信が不安定になる。**そもそも SES 非提供のリージョンもある**（§7.3） |
| ECR | ワーカーイメージを新リージョンの ECR へ再 push |
| タイトル資産 | th06/07/08/11 の `assets.tar.gz` 計 **約2.3GB** を新リージョンのS3へ再アップロード（クロスリージョンコピーなら転送料 $0.02/GB 程度で誤差） |
| 既存ジョブ | 出力は7日で自動削除されるため、移行期間中に旧リージョンを1週間残せば実質的な移行コストはゼロ |
| コード | `infra/bin/sattori.ts` の `region` 定数、`us-east-1e` レガシーAZ除外ハック（`infra/lib/sattori-stack.ts`）の撤去。**後者はむしろコードが綺麗になる** |

#### 7.1.1 なぜ ACM 証明書は us-east-1 必須なのか

**CloudFront がリージョンを持たないグローバルサービスであり、その API・設定を
us-east-1 のエンドポイントで一元管理しているため。** CloudFront ディストリ
ビューションに紐づくリソース（証明書、関数、キーグループ等）はすべて us-east-1 の
コントロールプレーンから参照される。ACM はリージョナルサービスで証明書は取得した
リージョンにしか存在しないので、CloudFront から見える唯一のリージョンである
us-east-1 に置く必要がある。

AWS 公式ドキュメント（*Requirements for using SSL/TLS certificates with CloudFront*）
の記述:

> To use an ACM certificate with a CloudFront distribution, make sure you request
> (or import) the certificate in the **US East (N. Virginia) Region (`us-east-1`)**.

> **AWS Region for AWS Certificate Manager**
> To use a certificate in AWS Certificate Manager (ACM) to require HTTPS between
> viewers and CloudFront, make sure you request (or import) the certificate in the
> US East (N. Virginia) Region (`us-east-1`).
>
> If you want to require HTTPS between CloudFront and your origin, and you're using
> a load balancer in Elastic Load Balancing as your origin, you can request or
> import the certificate in any AWS Region.

**重要な補足**: この制約が縛るのは**証明書だけ**であり、S3・Lambda・DynamoDB・
EC2 といった他のリソースを us-east-1 に置く理由にはならない。同じ理由で
**CloudFront 自体の料金・挙動もオリジンリージョンに依存しない**（§4.1）。

したがって「ACM が us-east-1 必須だからスタック全体も us-east-1」は論理的には
飛躍がある。ただし実務上は:

- CDK で単一スタックに収める限り、スタックのリージョン = 証明書のリージョンになる
- 分離するなら `crossRegionReferences: true` か、us-east-1 の証明書専用スタック +
  本体スタックの2本立てが必要
- 後者は「証明書スタックを先にデプロイする」というデプロイ順序の依存が生まれ、
  `pnpm run deploy` 一発で完結する現在の運用が崩れる

という程度には「us-east-1 に揃えておくと楽」という実利がある。`infra/bin/sattori.ts`
のコメントが挙げる2つの理由のうち、**ACM の話は正しく、コスト最適化の話は
誤りである**（§8.3-4）。

### 7.2 本質的なリスク：録画品質の再検証

これが移設を推奨しない最大の理由である。

- AGENTS.md「3. 常に踏まえておくべき設計判断」が明記する通り、**インスタンスタイプの変更は録画品質（重複フレーム率）
  に直結し、「同スペック帯・同価格帯だから安全」とは限らない**（`z1d.xlarge` の
  実績、th11 における `.xlarge` 帯の実時間伸長問題）。
- リージョンが変われば、`price-capacity-optimized` が実際に選ぶタイプ・世代・
  基盤ハードウェアの分布が変わる。us-east-1 で `c7i-flex.xlarge@us-east-1f` が
  選ばれていたところが、us-east-2 では `c6a.xlarge@us-east-2c` になる、といった
  変化が起きる。
- 候補タイプ自体は reports/27・40 で検証済みだが、**その検証は us-east-1 の実機で
  行われたもの**であり、他リージョンの同名タイプが同じ基盤世代・同じ性能で
  提供されている保証はない（AWSはリージョンごとに異なるハードウェア世代を
  同一インスタンス名で提供することがある）。
- したがって誠実にやるなら、**移設先で th06/07/08/11 それぞれのフルラン録画を
  複数タイプ分実測し、重複フレーム率を再検証する**必要がある。これは
  touhou-recorder の reports/27（6タイプ検証）や reports/40（th11 の .2xlarge 検証）
  と同等の工数を意味する。

### 7.3 リージョン別の追加懸念

| 候補 | 懸念 |
| --- | --- |
| **eu-south-2**（最安） | **SES が提供されていない**（下記）。加えて候補タイプが `.xlarge` で3種・`.2xlarge` で2種しかなく、Issue #29 で分散させた意味が大きく失われ `InsufficientInstanceCapacity` 再発リスクが上がる。オプトインリージョンであり、新サービスの提供開始も遅れがち |
| **ap-south-1** | `.2xlarge` は3種。`c7a` 系が使えない。日本からの物理的距離は近くない |
| **eu-north-1** | `c6a` 系が一切ない。`.2xlarge` の中断頻度が 10-15% で us-east-1 より劣る |
| **ap-northeast-2** | `.2xlarge` は `c6i`/`c7i` の2種のみ。th11 の耐性が明確に落ちる |
| **us-east-2** | **候補6タイプ・4タイプすべてが揃う唯一の安価リージョン**。S3/EBS/DynamoDB 単価は us-east-1 と完全同額。ACM を us-east-1 に残すクロスリージョン構成も地理的に近く扱いやすい。ただし `.2xlarge` の中断頻度は us-east-1 の 5-10% に対し 10-15% |
| **us-west-2** | タイプ網羅性は us-east-2 と同等で4AZ。ただし `.2xlarge` の中断頻度が 15-20% と最も悪く、th11 のリトライ増が節約分を食う可能性が高い |

#### SES 非提供リージョンに注意

AWS 公式の SES エンドポイント一覧を確認したところ、**以下のリージョンには SES が
存在しない**。現行アーキテクチャはマジックリンク送信（`requestMagicLink`）と完了
メール送信（`sendCompletionEmail`）の双方が SES に依存しているため、これらの
リージョンは単独では成立しない。

| SES 非提供リージョン | 備考 |
| --- | --- |
| **eu-south-2** (スペイン) | **本調査で最安だったリージョン**。オプトイン済み |
| ap-east-1 (香港) | 未オプトイン |
| ap-east-2 (台湾) | 未オプトイン |
| mx-central-1 (メキシコ) | 未オプトイン |
| ap-southeast-6 (ニュージーランド) | 未オプトイン |
| ap-southeast-7 (タイ) | 未オプトイン |

厳密には**絶対的なブロッカーではない**。SES は Lambda から SDK 経由で呼ぶだけなので、
`SESv2Client({ region: "us-east-1" })` のようにクライアントのリージョンだけ別に
向ければ動作する。ただしその場合:

- ドメイン ID・DKIM・本番アクセスを別リージョンで維持し続けることになる
- AGENTS.md「3. 常に踏まえておくべき設計判断」が掲げる「単一クラウドに寄せて運用を単純化」という設計原則が
  リージョン境界で崩れる
- 障害時の切り分け対象が増える

**最安リージョンを選ぶために構成を複雑化させる価値は、月 $19 の節約には見合わない。**

#### まとめ

**もし将来どうしても移すなら `us-east-2` 一択**。安さの順位は実測5位だが、
「タイプ網羅性（6/4種すべて）・非EC2料金の us-east-1 との同額性・SES 提供あり・
ACM を us-east-1 に残す場合の地理的近さ」を含めた総合では最良である。

## 8. 判断

### 8.1 移設は現実的か

**技術的には現実的（1〜2日の作業＋SES再申請待ち）だが、録画品質の再検証を含めると
1〜2週間規模。** 検証を省略して移設するのは、このプロジェクトが積み上げてきた
品質検証の資産（touhou-recorder reports/12〜40）を捨てることに等しく、推奨できない。

### 8.2 コスト的に有利なリージョンはあるか

**ある。ただし差は小さく、最安リージョンには別の制約がある。**

- 純粋な Spot 価格（実測）では `eu-south-2` < `ap-south-1` < `eu-north-1` <
  `ap-northeast-2` < `us-east-2` < `us-west-2` < **`us-east-1`（現行, 7位）**
- ただし最安の `eu-south-2` は **SES 非提供** かつ候補タイプが薄く、実質的に候補外。
- **未オプトインの16リージョンも全件推計したが、有力候補はゼロ**（§2.3）。
  すべて候補インスタンスタイプが1〜5種しかなく、th11 用 `.2xlarge` に至っては
  14/16 リージョンが1〜2種しか提供していない。
- 総コストでの節約は月 **$4.78〜19.28**、年 **$57〜231**。
- 実務的な制約をすべて満たす最良候補は **`us-east-2`（月 -$5.76 / 年 -$69）**。

### 8.3 推奨アクション

1. **リージョン移設は行わない。** 年 $69〜231 の節約に対して、録画品質の
   再検証リスクとクロスリージョン ACM/SES の運用複雑化が見合わない。
2. **代わりに動画サイズを削る。** `upscale.py` / `recording_common.py` の
   `-crf 18` を 20〜22 帯で試験し、視覚品質が許容範囲なら切り替える。
   CloudFront 無料枠1TBの余裕確保が最優先課題。
3. **CloudFront の転送量を監視対象に加える。** 現状 0.99TB/月（月1000録画換算）で
   無料枠の 99%。月間 800GB を超えたらアラートする CloudWatch アラームを設ける。
4. **記録として残す**: 「us-east-1 はコスト最適だから選んだ」という説明は正確では
   ない。us-east-1 の実質的な利点は **①ACM証明書が同一リージョンで完結する（§7.1.1）、
   ②Spotプール数が全リージョン最多（30プール/6タイプ）で起動失敗耐性が最高**の
   2点であり、Spot単価はむしろ中位（34リージョン中の実測7位）である。
   `infra/bin/sattori.ts` のコメントにある「コスト最適化に加え」という記述は、
   この調査結果に合わせて修正するのが望ましい。修正案:

   ```ts
   // us-east-1固定。Web配信CloudFrontにアタッチするACM証明書はus-east-1必須であり
   // (CloudFrontはグローバルサービスでコントロールプレーンがus-east-1にある)、
   // 加えてSpotキャパシティプール数が全リージョン最多(30プール/6タイプ)で
   // 起動失敗耐性が最も高い。なおSpot単価自体は最安ではなく全34リージョン中7位で、
   // us-east-2なら約8%安い(docs/research/aws-region-cost-analysis.md)。
   ```
5. **将来の再検討トリガー**: 月間録画数が **5,000回を超えたら**再検討する。
   その規模なら us-east-2 移設で年 $350 前後、eu-south-2 なら年 $1,150 前後の
   節約となり、検証工数に見合う可能性がある。ただしその頃には CloudFront 超過が
   月 $340 以上に達しているはずで、**やはり動画サイズの削減が先**である。

## 付録: 再現手順

調査に使ったスクリプトは一時ディレクトリに置いたもので、リポジトリには含めて
いない。再現する場合は以下の要領:

```bash
# 1. 全リージョンのSpot価格履歴(30日)を取得
aws ec2 describe-spot-price-history --region <REGION> \
  --instance-types c7i.xlarge c7a.xlarge c6a.xlarge c6i.xlarge c7i-flex.xlarge c5a.xlarge \
                   c6i.2xlarge c6a.2xlarge c7i.2xlarge c7a.2xlarge \
  --product-descriptions "Linux/UNIX" \
  --start-time "$(date -u -d '30 days ago' +%Y-%m-%dT%H:%M:%S)"

# 2. 候補タイプのAZ提供状況
aws ec2 describe-instance-type-offerings --region <REGION> \
  --location-type availability-zone \
  --filters "Name=instance-type,Values=c7i.xlarge,..."

# 3. 中断頻度(Spot Instance Advisor の公開データ)
curl -s https://spot-bid-advisor.s3.amazonaws.com/spot-advisor-data.json

# 4. 各サービスのリージョン単価(us-east-1のエンドポイントから全リージョン分を取得可能)
aws pricing get-products --region us-east-1 --service-code AmazonS3 \
  --filters Type=TERM_MATCH,Field=regionCode,Value=<REGION> \
            Type=TERM_MATCH,Field=productFamily,Value=Storage \
            Type=TERM_MATCH,Field=storageClass,Value="General Purpose"

# 5. リージョン別のサービス提供状況(未オプトインリージョンも確認できる)
aws ssm get-parameters-by-path --region us-east-1 \
  --path "/aws/service/global-infrastructure/regions/<REGION>/services" \
  --query 'Parameters[].Value' --output text
# ※ Step Functions のサービスコードは "states" ではなく "stepfunctions"

# 6. 未オプトインリージョンのSpot価格推計
#    describe-spot-price-history は AuthFailure になるため、
#    オンデマンド価格 × (1 - Spot Advisorの節約率) で推計する(§2.3)
```

**注意**

- `awscli@HakataMatrix` ユーザーには `ses:GetAccount` / `ses:ListEmailIdentities`
  の権限がないため、SES の本番アクセス状況は CLI から確認できなかった
  （マネジメントコンソールで要確認）。なお**リージョンごとの SES 提供有無**は
  上記コマンド5 と AWS 公式ドキュメント
  （`docs.aws.amazon.com/general/latest/gr/ses.html`）で確認済み。
- S3 Standard 単価は一部リージョン（eu-south-1 / af-south-1 / ap-south-2 /
  ap-east-2 / ap-southeast-6）で Price List API が `volumeType: Standard` を
  返さなかったため、同一価格帯である Intelligent-Tiering Frequent Access の
  第1階層を代理値として使用した。総額への影響は $1 未満。
