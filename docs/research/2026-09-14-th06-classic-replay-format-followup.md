# 東方紅魔郷リメイク2作リプレイフォーマットの追加調査（Issue #238）

- **検証日**: 2026-09-14
- **対象**: [`th06-classic-replay-format.md`](th06-classic-replay-format.md)（2026-09-10、以下「元調査」）の
  §6「分かっていないこと」のうち、追加リプレイがあれば確定できるとしていた項目
- **環境**: 前回と同じ（実機のリプレイ選択画面を真値として突き合わせ）
- **結論**: 4項目中2項目（スペルプラクティスの難易度・ステージ添字の意味）を確定。
  クリア判定（`cleared`）は今回も手がかりが見つからず未確定のまま。ゲームモード値2は
  「ステージプラクティス自体は存在するがリプレイ保存機能を持たない」ことが分かった
  だけで、正体は依然不明

前回の調査（2026-09-10）は13件のリプレイで判明した項目を実装したが、6面/Extraでの
ゲームオーバー・スペルプラクティスの難易度違いサンプル・ゲーム内スペル番号対応表が
手元になく、4項目が未確定のまま残っていた（元調査§6）。本調査はIssue #238で
報告者から追加提供された7件のリプレイと、ゲーム内 Spell Practice メニューから収集された
番号対応表を使い、それらを埋められるか検証した。

## 目的

元調査§6の4項目（クリア判定・スペルプラクティスの難易度・ゲームモード値2・
スペルプラクティスのステージ添字）を、追加データで確定できるか確認する。

## 方法

Issue #238 で次の7件のリプレイが `packages/replay-parser/test-fixtures/` に追加された。

| ファイル | 内容 |
| --- | --- |
| `th06c/th6_07.rpy` | Extra、ゲームオーバー |
| `th06c/th6_08.rpy` | Extra、全クリア |
| `th06nc/th6_08.rpy` | Lunatic、6面到達でゲームオーバー |
| `th06nc/th6_22.rpy` | Lunatic、全クリア |
| `th06nc/th6_28.rpy` | スペルプラクティス No.33 |
| `th06nc/th6_29.rpy` | スペルプラクティス No.34 |
| `th06nc/th6_30.rpy` | スペルプラクティス No.126 |

加えて、ゲーム内 Spell Practice メニューから収集された「スペル番号→難易度→カード名」の
対応表（134件、`packages/replay-parser/src/data/th06nc/spellcards.json`）が提供された。

**クリア判定**: `th6_07`/`th6_08`（th06c、同一難易度・同一到達ステージの GO/Clear ペア）と
`th6_08`/`th6_22`（th06nc、同条件）について、

1. 復号後のヘッダ全域（0x00 〜 ステージオフセット配列の手前）をバイト単位で diff
2. 最終到達ステージのスナップショット全体（未使用領域含む）を比較
3. 最終ステージの入力ログ末尾（番兵 `9999999` の出現パターン、元調査§3.4）を比較

の3通りで、GO/Clear で値が変わる位置を洗った。

**スペルプラクティスの難易度・ステージ添字**: `th6_28`/`th6_29`/`th6_30` を parser
（変更前のもの）でパースし、`splits[0].stage`（＝スペルプラクティスが使うステージ
オフセット配列の添字＋1）を `spellcards.json` の対応するカード名・難易度、および
Issue #238 でユーザーが実機確認したステージ番号と突き合わせた。

**ゲームモード値2**: Issue #238 の報告者に New Classic のゲーム内メニューを直接
確認してもらった。

## 結果

### クリア判定: 手がかり無し（未確定のまま）

th06c ペア（`th6_07` vs `th6_08`）・th06nc ペア（`th6_08` vs `th6_22`）のいずれも、
ヘッダ全域・最終ステージスナップショット・入力ログ末尾のいずれの比較でも、
チェックサム・0x0c/0x10 の「不明 u16」・鍵バイト・スコアという既知フィールド以外に
差が無かった。特に th06c の最終ステージは GO/Clear どちらも番兵が二重に書かれており
（元調査§3.4 の記述通り常に二重化するだけ）、th06nc はどちらも二重化しなかった
（バッファ末尾に達しているのみ）。ステージスナップショットの未使用領域（0x0c〜0x1f
相当）も両ファイルとも全て 0 で一致していた。

→ `cleared` はヘッダにもステージスナップショットにも専用のフラグ領域を持たない
可能性が高い。少なくとも今回の2ペアからは復元できず、`cleared: null` を維持する。

### スペルプラクティスの難易度: 確定

`spellcards.json` の `No.33`/`No.34` はどちらも「彩符「彩光乱舞」」（Hard / Lunatic）
だった。**1枚の原作スペルカードが難易度ごとに別番号を持つ**——元調査§6 item 2 の仮説
「スペル番号自体が難易度込みで採番されている」が実証された。

`th06.ts` の `readModeAndStage` は `spellcards.json` を組み込み、Spell Practice
リプレイの `difficulty` をこの対応表から復元するよう変更した（表に無い番号は従来通り
`null`）。`stage` にもカード名を付加した（例: `"Spell Practice No. 34 彩符「彩光乱舞」"`）。

### ゲームモード値2: 「ステージプラクティスにリプレイが存在しうる」が否定されたのみ

報告者がゲーム内メニューを確認した結果、**New Classic にステージプラクティス機能自体は
存在するが、リプレイの保存機能を持たない**ことが分かった（th19が丸ごとリプレイ保存機能を
持たないのと同種の欠如で、モードとしては存在する）。したがって「モード2はステージ
プラクティスに対応するリプレイである」という推測は撤回する——モード2に対応するリプレイが
存在する可能性自体が下がった。モード2の実際の意味（未実装の予約値など）は依然不明で、
該当するリプレイサンプルも無い。`parser` は引き続き `stage: "Mode 2"` として素通しする。

### スペルプラクティスのステージ添字: 確定

`No.33`/`No.34`（彩符、3面ボス紅美鈴のスペル）はステージオフセット配列の添字2
（`splits[0].stage === 3`）、`No.126`（禁忌「恋の迷路」、Extra のフランドールのスペル）は
添字6（`splits[0].stage === 7`）だった。いずれもユーザーが実機の Spell Practice
メニューで確認したステージ番号と一致した。元調査の唯一のサンプル（`No.108`、6面の
レミリア、添字5）と合わせて3面分のサンプルが「そのスペルが属する面の添字が使われる」
という仮説を裏付けたため、この解釈を確定とする。

## 考察・既知の限界

- クリア判定について、今回の2ペアはいずれも「その難易度で最も深いところまで到達できる
  ステージ」（th06c は Extra、th06nc は6面）での比較であり、より手前のステージで
  ゲームオーバーになったリプレイとの比較は行っていない。ただし元調査でも「6面到達済みかつ
  未クリア」と「全クリア」を分けるフラグが本命だったため、狙いとしては妥当なペアである。
  それでも見つからなかったことから、cleared 相当の情報がこの3変種のファイル形式には
  そもそも存在しない可能性を疑ってよい段階だと考える。
- ゲームモード値2はサンプルが依然0件のまま。「ステージプラクティスにはそもそも
  リプレイが存在しえない」という事実だけでは代替候補を絞り込めておらず、引き続き
  リプレイが手に入らない限り解決しない。
- スペルプラクティスの難易度・ステージ添字の確定は、いずれも `spellcards.json`
  という外部情報源（ゲーム内画面からの手動収集）に依存している。ファイル自体から
  独立に検証できる情報ではないため、対応表に誤りがあれば実装も誤る。
